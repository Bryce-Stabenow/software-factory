# ADR 0003: Bounded repository tools for real Codex planning

Status: accepted and smoke-tested on macOS with Codex CLI 0.153.4.

Use the official Codex app-server JSONL/stdio interface and CLI-managed sign-in. The factory never reads, copies, proxies, or stores OAuth tokens or API keys. Its child environment is allowlisted; CLI-managed authentication still uses `HOME` / `CODEX_HOME`. No direct Responses API or new account flow is introduced.

The current official documentation and installed CLI differ in some experimental fields. Generate version-specific schemas with `codex app-server generate-json-schema --experimental --out <temporary-directory>` when upgrading. This implementation uses `initialize` / `initialized`, `account/read`, `model/list`, `thread/start`, `turn/start`, `item/tool/call`, `item/completed`, `turn/completed`, and `turn/interrupt`. The client advertises experimental API support for app-owned dynamic tools. It verifies the effective configuration and the returned read-only policy and approval policy before starting a turn. An empty MCP table override merges with existing configuration, so a discovery process reads only the effective configuration, terminates, and restarts with each inherited server explicitly disabled before any thread is created. No configuration values are logged or persisted.

The planner runs against a per-run snapshot under the factory data directory, never the registered checkout. Git enumerates tracked and nonignored untracked files without optional locks or fsmonitor. Snapshots contain at most 1,000 text files, 256 KiB per file, and 20 MiB overall. Secret-like paths, Git metadata, factory data, build/dependency directories, symlinks, and binary files are omitted. Obvious token patterns are redacted before exposure. These exclusions are conservative heuristics, not a guarantee that arbitrary source contains no secrets; users choose which repositories to send to their provider.

Expose only `list_repository_files` and `read_repository_file`. The readers enforce an exact file allowlist, reject traversal/absolute paths and symlinks, and bound the number of calls. Shell, unified execution, plugins, MCP integrations, hooks, browser/computer tools, and subagents are disabled. The CLI's local code-mode **host** must remain available to dispatch dynamic tools; disabling it produces tool failures even though thread creation succeeds. Model code-mode is disabled. The provider also runs with `readOnly`, `networkAccess: false`, and `approvalPolicy: never`. Every unsupported server request is denied and durably recorded; no permission expansion is offered through plan approval. The CLI process itself needs network access for inference; the no-network policy applies to agent execution.

The installed stable `readOnly` shape does not include the documentation's newer restricted-read fields. This increment relies on the app-owned reader boundary for scoped repository reads and disables host-execution capabilities, rather than claiming the legacy sandbox alone restricts all host reads. Unknown/untrusted code execution is not enabled.

`model/list` supplies the catalog default or the user explicitly selects a model. A configured CLI model can differ from the catalog default and can be rejected for ChatGPT sign-in; the smoke test encountered this. The model is selected and recorded before the run, and never silently changed mid-run. Catalog membership and sign-in health do not prove entitlement; a completed inference turn does. No subscription balance is inferred.

Planning is a short-command / background-job workflow. Queue/run rows and domain events are persisted before dispatch. At most two planning jobs run concurrently. A task cannot have a second active job. Network work never runs inside a SQLite transaction or blocks normal command handling. A five-minute wall-clock limit, read-call limit, bounded protocol frames, `turn/interrupt`, and process-group termination bound failure and cancellation. Process PIDs, provider thread/turn IDs, selected model, and snapshot digest are recorded. Normal shutdown drains planning jobs before closing SQLite; the desktop allows five seconds for companion shutdown.

Only `turn.status === completed` plus schema-valid JSON and actual repository-read evidence can produce a proposal. A zero process exit code or partial output is insufficient. Snapshot digest changes reject the result. Clarification questions persist against the exact revision and block approval; answers start a fresh planning session. Revisions and feedback also start fresh sessions rather than relying on opaque provider history. All final plan approvals retain their exact revision/digest guard.

Failures and permission denials become visible `FAILED` / `BLOCKED` tasks. Retry is explicit and preserves prior runs. Restart reconciliation interrupts queued/in-flight records rather than blindly rerunning them. A previous live provider PID blocks a retry. Full scheduler leases and robust PID identity are deferred until mutating execution. Provider sessions are ephemeral; recorded IDs are diagnostic references, not a promise of session resume.

Official reference: [Codex app-server](https://learn.chatgpt.com/docs/app-server). Verification details: [verification record](../verification.md).

Development lifecycle: Vite 8 creates a replacement server before closing the previous one. The browser bridge therefore acquires its service lazily on the first authenticated command after listening, and its `closeServer` hook awaits a shared shutdown promise. This prevents two configurations in one process competing for the same database lock during hot restart.
